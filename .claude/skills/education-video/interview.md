# The interview

GATE 0 of `SKILL.md`. Read this before asking the first question.

**Open the question window unasked, and never bank questions for the end.** A question answered
after the script is written costs a rewrite; after the audio is locked, a re-record.

Use the `AskUserQuestion` tool — the click-the-option window with a free-text **Other** — not
questions buried in chat prose. Four per call, so **at least three calls and at least 10 questions
answered before GATE 1 opens.**

- **Every question must change what gets made.** If both answers produce the same film, it is not
  one of the ten. Cut it and ask a real one.
- **Options are concrete and mutually exclusive** — "5–7 min, nine scenes" beats "medium length".
  Recommendation first, marked as such.
- **Read the repo before asking.** Offer what you found as the first option. Asking what a
  two-minute grep would have told you spends a question and reads as inattention.
- **Batch by topic** so each window is coherent, and ask the most film-defining topics first.
- **Anything unresolved after the ten gets asked the same way, the moment it surfaces** — mid-script,
  mid-audio — in a window, not deferred to a list at the end.

## Cover at minimum, one question each

1. **Audience** — who watches, and what they already know.
2. **The source document** — which file is the source, and whether it is frozen.
3. **Evidence status** — what may be spoken as measured, versus simulated, specified, or estimated.
4. **Runtime and scene count** — the slot the film has to fill.
5. **Scope limits** — the explicit do-not-narrate list.
6. **The verdict** — the decision the film ends on, and which alternatives lost.
7. **Vocabulary** — terms to define on first use, terms to avoid entirely.
8. **Voice** — narrated or captions-only, whose voice, which language.
9. **Picture direction** — the visual register Claude Design should work in, and any diagram the
   source document already implies. Never *who* makes it: `SKILL.md` has settled that.
10. **Delivery** — where it is published, aspect ratio, caption requirement, deadline.
11. **Where the film's files live** — see below. Ask it; do not choose it.

Do not open GATE 1 on assumptions about any of these. An unanswered one is a question, not a default.

## Never ask about something the skill has already settled

**A question implies the answer is the user's to give.** Putting a settled thing in a window offers
freedom that does not exist, and either wastes one of the ten or — worse — gets an answer you then
have to refuse. These are decided, and stay out of every window:

- **the order of the four stages.** Not as a question, not as an option inside one, not "audio first
  or picture first?". It is the skill's one non-negotiable claim.
- **whether there is narration at all.** "Captions only" is not an option: with no audio, nothing
  sets the timing, and the whole method collapses into guesswork.
- **who draws the picture, or where it comes from.** Settled in `SKILL.md`.
- **whether the source document must be audited, or the script approved before recording.** Both are
  the process. Asking implies they could be skipped.

The test before every option you write: *if the user picks this, do I have to say no?* If yes, delete
the option. Ask what the film should **be**, never whether the method should hold.

## Where the film's files live

**Ask, and never default to putting them next to this skill.** A skill is a procedure that travels
between repositories; the films it produces are not part of it and must not accumulate inside it.
The same goes for any directory the user is packaging for reuse.

So establish at GATE 0: which directory holds the film's document, script, cue sheet and manifest,
and which holds its heavy audio takes and masters. Both belong to the user's project, not to the
tooling. If they have no preference, propose one and get it confirmed rather than assuming.

## How GATE 0 closes — the summary in bullets

**End the stage by playing back every answer as short bullets, and nothing else.** One line per
decision, in the interview's own order, so the user can scan the whole brief in one screen and catch
the one you got wrong. Not prose, not a table of trade-offs, not a re-argument of anything settled.

- **One line each**, in the form *thing: what was decided*. Six words where six will do.
- **Say plainly where two answers met** and how you reconciled them — that is where the
  misunderstanding will be, and it is invisible in the raw answers.
- **Name any question the user answered with free text**, in their words, not smoothed into yours.
- **Write the same summary to a file** in the film's directory, so the brief outlives the scrollback,
  and give its path.
- Then one question: **anything wrong here?** Wait for the answer before opening GATE 1.

## What a good answer changes

Worked example, from a film made with this skill. "Runtime and scene count" was answered *5–6
minutes, mirroring the reference*, which set the script's word budget at ~700 and made a first draft
of 815 words a trim rather than a discovery. Had it gone unasked, the trim would have arrived after
the audio was recorded, and the trim would have been a re-record.

That is the test for every question here: name the later rework it prevents. If you cannot, it is
not one of the ten.
